# Story Studio Android/Mobile usability audit

Scope: the existing `/stories/create` mobile presentation only. The Computer Studio, editor engine, story viewer and unrelated product areas are unchanged.

## Current journey and observed friction

| Area                          | Evidence in the current implementation                                                                                                                                                              | Usability issue                                                                                                                                                                            | Redesign direction                                                                                                                                                                   |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Entry and editing             | `StoryStudioDeviceSelector` chooses the Mobile presentation; `StoryEditorPage` owns the same scene state and editor panels as Computer Studio.                                                      | The device choice is clear; after entry, the mobile editor presents nearly every desktop tool in a permanently visible, horizontally scrolling rail.                                       | Keep common actions directly visible and move less common tools into a labelled More panel.                                                                                          |
| Top actions                   | The mobile header in `story-editor-page.tsx` shows Close, Undo, Redo, Preview and Post.                                                                                                             | The icon-only actions have no text labels, and “Post” opens More → Share, where the actual action is to download or hand off to another app. It does not publish a VELORI story.           | Keep accessible icon names, label the primary forward action accurately, and use the existing authenticated Stories publisher for VELORI publishing. Keep external sharing distinct. |
| Main tools                    | `studioTools` currently exposes Media, Text, Sticker, Shape, Music, Layout and More at the same level.                                                                                              | Seven actions compete for limited width; Music and Layout are less frequent than adding or editing content.                                                                                | Prioritize Media, Text, Stickers and Shapes; disclose Music, Layout, Brand Kit, collaboration and export/share contextually.                                                         |
| Panels and preview            | The shared `m.aside.story-editor-sidebar` is fixed above the bottom storyboard and tool rail.                                                                                                       | A selected panel overlays the lower canvas and can consume a large portion of a short viewport. Tool changes remount the panel, making context less obvious.                               | Keep a compact, dismissible contextual sheet, preserve the same scene/selection, and provide predictable close/return controls.                                                      |
| Storyboard                    | `SlideNavigator` is fixed above the toolbar on mobile.                                                                                                                                              | It is always visible even when the user is focused on editing one slide, using valuable vertical space.                                                                                    | Retain slide access but collapse it to a compact count until expanded.                                                                                                               |
| Media and editing             | `MediaTools`, `TextTools`, `StickerTools` and `ShapeTools` share the same operations across layouts.                                                                                                | The available actions are real, but their grouping and persistent presence make the editor look more complex than its common workflow. No Draw tool exists in the registered tool set.     | Reuse current tools; do not advertise drawing or other unimplemented capabilities. Keep direct canvas manipulation and history shared.                                               |
| Publishing and audience       | `ExportPublishPanel` downloads PNG/MP4 or hands files to external apps. The existing `/stories` composer owns authenticated upload, audience choice, storage, row creation, cleanup and activation. | Studio’s “Post” label overpromises; export/share and VELORI publishing are conflated. The native publisher supports Public, Followers, Close friends and Only me, defaulting to Followers. | Add an explicit mobile review/publish step using the existing story backend and audience choices. Leave external sharing under Export & share.                                       |
| Error/retry                   | Editor errors use a global dismissible alert; the existing composer reports upload/publish failures and cleans up failed story records.                                                             | The editor does not own native publish state, so it cannot show real upload progress or a native publish result.                                                                           | Surface generation/upload progress and actionable failure in the review flow; retain the project for retry and prevent duplicate submits.                                            |
| Responsive and touch behavior | `story-editor.css` sizes the mobile canvas from `100dvh`, uses safe-area insets and rearranges controls in landscape. Object transforms use the shared canvas.                                      | The overlay sheet and always-open storyboard compete with canvas height; keyboard-open behavior and real Android ergonomics were not previously covered by the Story Studio tests.         | Verify narrow, standard, landscape and keyboard states in browser emulation; keep browser evidence distinct from physical-device claims.                                             |

## Verified boundaries and limitations

- Computer Studio and Android/Mobile Studio use the same `StoryEditorPage`, `StoryCanvas`, scene state, tool components, history and export renderer.
- The existing native story publisher in `StoriesPage.createStory` is the only implemented VELORI publish path. It uses authenticated Supabase inserts, the private `story-media` bucket, current audience values, story preferences and cleanup on failure.
- `ExportPublishPanel` is external export/share, not VELORI publishing; local schedule entries are reminders, not scheduled publication.
- The current browser MP4 export does not mix audio. Native MP4 generation and browser codec support must be stated rather than silently falling back.
- No Draw/eraser tool is registered. Do not add a nonfunctional Draw affordance.
- Physical Android hardware was not available for this audit; viewport tests are Chromium emulation.
