## Current live deployment boundary

The 2026-10-05 read-only migration probe returned 30 contract failures. Nine correspond to local migration 037 (campaign/notification fields, dispatch and receipt-sync functions, two indexes, and a trigger); the remaining failures correspond to migrations 035/036 (story/reel media visibility and expired-storage cleanup). The live verifier also returned six failures for those absent changes: the notification schema/RPC contracts, cleanup-token configuration, and cleanup endpoint. Other existing API, Storage, social RPC, and CORS checks passed.

The local implementation is reviewable, but **the live site does not yet contain migrations 034–037 or the updated Edge Function**. Browser screenshots and workflows for the latest local changes have not been run. Do not label the platform production-ready from the local build or route sweep.

## Required next verification

1. Run the reviewed backend deployment workflow after the deployment is explicitly authorized; confirm that the migration ledger and read-only schema probe are clean.
2. In a non-production project, test campaign sends for all users and each account type, verify preference filtering and actual recipient counts, mark read and confirm the receipt updates, then withdraw and confirm timeline deletion.
3. Use separate accounts to test story/reel metadata and Storage reads across owner, eligible follower, non-follower, private profile, hidden/blocked creator, expired item, and moderation states.
4. Enqueue test story and trash-post media objects, run the cleanup workflow, and verify the intended objects are gone while unrelated media remains.
5. Run real signup/confirmation/recovery and admin/public CMS/theme/navigation/error-page flows, followed by browser checks at mobile and desktop widths.
