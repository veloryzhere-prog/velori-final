# VELORI content and publication rules

## Strict authenticity requirements

- Do not invent published jobs, company locations, personnel, completed products, customer statistics, security certifications or official contact addresses.
- Do not make up VELORI AI development percentages.
- Never pretend that developer APIs are publicly available before deployment.
- Unimplemented features must be marked **In Development**, **Preview** or **Coming Soon**.
- Never present sample API keys as real credentials.
- Do not use references to Meta products as claims of affiliation.
- Legal templates must be reviewed before publication.
- Always keep the exact product name VELORI and parent brand VELORYZ.
- Use the real configured production domain from environment settings or deployment configuration; do not assume a domain belongs to the project merely because it was mentioned.

---

## Current content ownership

Page Studio stores body HTML, CSS and JavaScript separately. Draft edits are reviewed in desktop/tablet/mobile previews, then published using the existing permission and reauthentication controls. Prior code and unfinished drafts were retained. Bundled templates are fallback/source material, not a license to overwrite later administrator edits automatically.

## Expanded-system publication

Only approved jobs and reviewed employers appear publicly. Do not index applicant details or admin dashboards. Publish a legal policy only after an authorized reviewer approves the exact content/version/language/effective date. No job fees, AI completion percentages, response-time promises or security certification claims may be invented. The new schema is a proposal, not evidence that these controls are installed.
