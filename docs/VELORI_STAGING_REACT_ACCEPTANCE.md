# VELORI staging React dependency installation and preview acceptance

This procedure validates a generated React project outside the VELORI app. The current source generator exports React files but does not install dependencies, build generated projects, or embed a live React preview runtime in FORGE. Treat successful isolated acceptance as a required deployment blocker, not as a capability already present in the app.

## Preconditions

- The checked-out source is the verified project archive or the current repo working tree.
- A real React project has been generated by an authenticated staging request and exported from FORGE as a source ZIP.
- A disposable VM/container is prepared with no host credentials, mounted secrets, or access to personal files.
- Network access is allowed only for dependency installation; disable egress before executing generated code.

## 1. Dependency installation

Extract the generated project ZIP into a disposable directory and run from that project root:

```bash
pnpm install --no-frozen-lockfile
```

Expected result:

- Dependency installation completes without private credentials or environment secrets.
- No secret values are written into the working tree or build output.
- The generated starter does not include a lockfile; record the resolved dependency tree and generated lockfile as test artifacts.

## 2. Production build verification

Run the generated project's own build script:

```bash
pnpm run build
```

Expected result:

- The build completes successfully.
- The generated React app produces its production bundle under `dist/`.
- The build succeeds after dependency installation with no credentials or runtime secrets.
- Scan the generated `dist/` and source archive for secret-like values before discarding the sandbox.

## 3. Isolated preview verification

After the build, start the app in the disposable environment. Bind only to loopback:

```bash
pnpm run preview -- --host 127.0.0.1 --port 4173
```

Expected result:

- Confirm the process listens only on `127.0.0.1:4173`; reject the run if it binds to `0.0.0.0` or a public interface.
- Open the preview in a browser running inside the same disposable environment and exercise at least one generated interaction.
- No undeclared service or credential is required for build or preview.
- Terminate the process and destroy the sandbox after recording results.

## 4. Browser acceptance checklist

- The landing page renders and the navigation loads.
- The generated React app has no console or network errors during the preview.
- A generated interaction works and the app renders at desktop and mobile viewport sizes.
- The VELORI source UI retains the authenticated, server-managed AI consent disclosure.
- Generated source stays local unless the user explicitly exports it.

## 5. Acceptance gate

Do not claim integrated React preview support or proceed with production rollout of that capability unless:

- dependency installation succeeded from an actual generated-project ZIP in a clean sandbox;
- the isolated generated-project build passed;
- the loopback-only preview loaded without runtime errors and interactions worked;
- the generated source and output were checked for secret leakage;
- the sandbox was destroyed and evidence retained without personal or credential data.

## Current limitation

The VELORI app's own `pnpm run build` only compiles VELORI. It does not prove that generated React source installs or builds. FORGE currently labels React projects as source/ZIP export only, with no configured local runtime. This acceptance must be performed separately by the staging operator until an isolated generated-project runtime is implemented and approved.
